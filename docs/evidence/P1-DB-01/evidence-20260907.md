## R2 — Client/fds-engine 직접 DB 접근 차단 (자격증명 부재 vs 네트워크 차단 구분)

**기존 지적**: env 섹션 부재는 자격증명 미보유만 증명, 네트워크 차단은 별도 증명 필요.

**네트워크 계층 실측 (fds-engine pod → db01:5432)**:
```bash
$ kubectl exec -it fds-engine-84bfcc7cb6-4vstz -n fds -- python3 -c "... socket.connect(('10.1.93.55', 5432)) ..."
실패: ConnectionRefusedError(111, 'Connection refused')
```
- fds-engine은 DATABASE_URL 등 credential을 아예 보유하지 않을 뿐 아니라(env 섹션 부재, 기존 확인), TCP 포트 자체에도 도달하지 못함(Connection Refused) — 자격증명 부재와 별개로 네트워크 계층에서도 차단됨을 실측으로 확인
- 참고: db01 자기 자신(10.1.93.55)의 hostssl 거부(R3 이후 섹션)는 Source가 db01 자신인 별도 사례이며, 이 항목(fds-engine Source)과는 구분되는 시험임

**상태**: RESOLVED (edge01/fds 임시 클러스터 범위) — Client(fds-engine) Source의 자격증명 부재 + 네트워크 계층 차단을 raw 근거로 구분 확인.
